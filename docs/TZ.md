# Техническое задание (ТЗ) — CV Builder

## 📖 Описание проекта
Необходимо реализовать веб-приложение **CV Builder** (конструктор резюме), требования и дизайн которого представлены в Notion (см. раздел [🔗 Ресурсы](#-ресурсы)).

- **Формат работы:** Парная разработка с другим стажёром (назначается ментором для отработки командного взаимодействия).  
  > *Примечание:* При отсутствии напарника задача выполняется индивидуально в полном объёме до дедлайна.
- **Вводный этап:** После изучения требований обязателен созвон с ментором для согласования стека технологий (UI-библиотека, State Management и сопутствующие инструменты).
- **Дедлайн:** 4 недели с момента старта.

---

## 🛠️ Стек технологий и архитектура

| Направление | Технологии / Инструменты | Примечание |
|---|---|---|
| **Фреймворк** | [Next.js](https://nextjs.org/) (React 19) | Страницы реализуются по стратегии **SSR / SSG** |
| **API & Data Fetching** | GraphQL + Apollo Client | Локально настроенный GraphQL-бэкенд |
| **Управление состоянием** | State Management (Redux Toolkit / Zustand / MobX / Jotai) | Согласовывается с ментором |
| **Интерфейс** | Выбранная UI-библиотека (Tailwind CSS, Shadcn UI, MUI, Ant Design и т.д.) | Адаптивная вёрстка под различные экраны |
| **Unit-тестирование** | [Vitest](https://vitest.dev/) + [React Testing Library](https://testing-library.com/) | Покрытие **> 80%** |
| **E2E-тестирование (Extra)** | [Playwright](https://playwright.dev/) или [Cypress](https://www.cypress.io/) | Сквозные тесты на ключевой функционал |

---

## 📌 Основные требования

- [ ] **Next.js архитектура:**
  - Корректная настройка маршрутизации (App Router / Pages Router).
  - Применение SSR (Server-Side Rendering) и SSG (Static Site Generation) там, где это применимо.
- [ ] **Функционал:**
  - Полная реализация пользовательских сценариев согласно ТЗ в Notion.
  - Динамические запросы к GraphQL API (Apollo Client).
- [ ] **State Management:**
  - Хранение и обработка глобального и локального состояния приложения.
- [ ] **UI / UX:**
  - Качественная адаптивная вёрстка.
  - Интеграция компонентов из выбранной UI-библиотеки.
- [ ] **Тестирование:**
  - Unit-тесты с покрытием кода более **80%**.
  - *(Extra)* E2E-тесты на все основные сценарии приложения.
- [ ] **Согласование:**
  - Перед началом активной разработки согласовать с ментором библиотеки (UI, state manager и др.).

## 📤 Формат сдачи задачи

1. **GitHub-репозиторий:**
   - Исходный код проекта.
   - Осмысленные, структурированные коммиты (рекомендуется Conventional Commits).
2. **README.md:**
   - Краткое описание функциональности проекта.
   - Список используемых зависимостей.
   - Пошаговая инструкция по установке и локальному запуску.
   - Инструкция по запуску unit-тестов.
   - *(Extra)* Описание структуры и тест-кейсов для E2E-тестов.
3. **Демо-презентация:**
   - Презентация готового приложения ментору (длительность: до 30 минут).
   - Ответы на технические вопросы ментора.

- [ ] Покрытие приложения unit-тестами составляет **более 80%**.
- [ ] *(Extra)* Наличие и стабильное прохождение E2E-тестов.
