# Техническое задание (ТЗ) — CV Builder

## 📖 Описание проекта
Необходимо реализовать веб-приложение **CV Builder** (конструктор резюме), требования и дизайн которого представлены в Notion (см. раздел [🔗 Ресурсы](#-ресурсы)).

- **Формат работы:** Парная разработка с другим стажёром (назначается ментором для отработки командного взаимодействия).  
  > *Примечание:* При отсутствии напарника задача выполняется индивидуально в полном объёме до дедлайна.
- **Вводный этап:** После изучения требований обязателен созвон с ментором для согласования стека технологий (UI-библиотека, State Management и сопутствующие инструменты).
- **Дедлайн:** 4 недели с момента старта.

## 🛠️ Стек технологий и архитектура

| Направление | Технологии / Инструменты | Примечание |

### Data fetching: без Apollo Client

**Apollo Client не используется.** Проект на Next.js (App Router), поэтому загрузка, кэширование и обновление данных выполняются средствами фреймворка:

- **Чтение данных** — запросы к GraphQL-бэкенду из **Server Components** (обычный `fetch` с `POST` и телом GraphQL-запроса), без клиентского рантайма и без дублирования кэша.
- **Кэширование и инвалидация** — кэш `fetch` Next.js: `next: { revalidate, tags }`, `revalidateTag` / `revalidatePath`.
- **Мутации** — **Server Actions** с последующей инвалидацией затронутых тегов/путей.
- **Клиентское состояние** — только UI-состояние (черновик формы в редакторе) через согласованный state manager; серверные данные в глобальный клиентский store не дублируются.

**Почему:** Apollo — тяжёлый клиентский слой с собственным кэшем, который дублирует кэширование Next.js и усложняет SSR. Нативный подход даёт меньше зависимостей, меньше клиентского JS и корректную работу SSR/SSG «из коробки».

> ⚠️ Отступление от исходной формулировки требований (там указан Apollo Client) — **согласовать с ментором** до начала активной разработки.

## 📌 Основные требования

- [ ] **Next.js архитектура:**
  - Корректная настройка маршрутизации (App Router / Pages Router).
  - Применение SSR (Server-Side Rendering) и SSG (Static Site Generation) там, где это применимо.
  - Кэширование и инвалидация серверных данных средствами Next.js (`fetch` cache, `revalidateTag` / `revalidatePath`).
- [ ] **Функционал:**
  - Полная реализация пользовательских сценариев согласно ТЗ в Notion.
  - Запросы к GraphQL API из Server Components; мутации — через Server Actions.
- [ ] **State Management:**
  - Хранение и обработка глобального и локального состояния приложения.
- [ ] **UI / UX:**
  - Качественная адаптивная вёрстка.
  - Интеграция компонентов из выбранной UI-библиотеки.
- [ ] **Тестирование:**
  - Unit-тесты с покрытием кода более **80%**.
  - *(Extra)* E2E-тесты на все основные сценарии приложения.
- [ ] **Согласование:**
  - Перед началом активной разработки согласовать с ментором библиотеки (UI, state manager и др.).
